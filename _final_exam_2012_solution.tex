\section{Bài 1: Coding Guideline cho thiết kế IP (1.5 điểm)}

\subsection{a) Áp dụng Coding Guideline viết lại đoạn code Verilog}
Dưới đây là mã nguồn Verilog của module \texttt{LCD\_Controller} sau khi áp dụng các nguyên tắc chuẩn hóa thiết kế Lõi IP (IP Core Design Guidelines) theo chuẩn ANSI Verilog-2001:

\begin{lstlisting}[caption={LCD\_Controller.v đã áp dụng Coding Guidelines}]
module LCD_Controller #(
    parameter CLK_DIV = 16  // Parametrization of clock division limit
)(
    // Host Side Interface
    input wire [7:0] i_data,      // 8-bit input data from Host
    input wire       i_rs,        // Register Select input
    input wire       i_start,     // Operation Start trigger
    output reg       o_done,      // Operation Done flag
    input wire       clk,         // System Clock
    input wire       rst_n,       // Asynchronous Active-Low Reset
    
    // LCD Interface
    output wire [7:0] o_lcd_data,  // 8-bit Data to LCD
    output wire       o_lcd_rw,    // Read/Write select (Always Write = 0)
    output reg        o_lcd_en,    // LCD Enable control signal
    output wire       o_lcd_rs     // LCD Register Select
);

    // Finite State Machine (FSM) State Parameters
    localparam [1:0] ST_IDLE    = 2'b00,
                     ST_SETUP   = 2'b01,
                     ST_EN_HIGH = 2'b10,
                     ST_EN_LOW  = 2'b11;

    // Internal Registers
    reg [4:0] r_cont;        // Clock divider counter
    reg [1:0] r_st;          // Current state register
    reg       r_pre_start;   // Register for start edge detection
    reg       r_m_start;     // Internal transaction in-progress flag

    // Combinational Assignments (Only write to LCD, bypass i_rs to o_lcd_rs)
    assign o_lcd_data = i_data;
    assign o_lcd_rw   = 1'b0;
    assign o_lcd_rs   = i_rs;

    // Sequential Logic Block
    always @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            o_done       <= 1'b0;
            o_lcd_en     <= 1'b0;
            r_pre_start  <= 1'b0;
            r_m_start    <= 1'b0;
            r_cont       <= 5'd0;
            r_st         <= ST_IDLE;
        end else begin
            // Input Edge Detection (Detect posedge of i_start)
            r_pre_start <= i_start;
            if ({r_pre_start, i_start} == 2'b01) begin
                r_m_start <= 1'b1;
                o_done    <= 1'b0;
            end

            // FSM Processing Block
            if (r_m_start) begin
                case (r_st)
                    ST_IDLE: begin
                        r_st <= ST_SETUP;
                    end
                    
                    ST_SETUP: begin
                        o_lcd_en <= 1'b1;
                        r_st     <= ST_EN_HIGH;
                    end
                    
                    ST_EN_HIGH: begin
                        if (r_cont < CLK_DIV) begin
                            r_cont <= r_cont + 1'b1;
                        end else begin
                            r_st   <= ST_EN_LOW;
                        end
                    end
                    
                    ST_EN_LOW: begin
                        o_lcd_en  <= 1'b0;
                        r_m_start <= 1'b0;
                        o_done    <= 1'b1;
                        r_cont    <= 5'd0;
                        r_st      <= ST_IDLE;
                    end
                    
                    default: begin
                        r_st      <= ST_IDLE;
                    end
                endcase
            end
        end
    end

endmodule
\end{lstlisting}

\subsection{b) Liệt kê các Guideline đã áp dụng được}
Các quy chuẩn thiết kế Lõi IP đã được áp dụng triệt để bao gồm:
\begin{enumerate}
    \item \textbf{ANSI C/Verilog-2001 Port Syntax}: Tích hợp trực tiếp hướng (\texttt{input/output}) và kiểu dữ liệu (\texttt{wire/reg}) trong ngoặc khai báo module, giúp loại bỏ việc khai báo lặp lại, nâng cao tính trực quan và giảm thiểu sai sót.
    \item \textbf{Quy tắc đặt tên biến có hệ thống (Naming Conventions)}:
    \begin{itemize}
        \item Các tín hiệu ngõ vào sử dụng tiền tố \texttt{i\_} (ví dụ: \texttt{i\_data}, \texttt{i\_rs}, \texttt{i\_start}).
        \item Các tín hiệu ngõ ra sử dụng tiền tố \texttt{o\_} hoặc \texttt{o\_lcd\_} (ví dụ: \texttt{o\_done}, \texttt{o\_lcd\_data}, \texttt{o\_lcd\_en}, \texttt{o\_lcd\_rs}).
        \item Tín hiệu xung nhịp hệ thống viết thường thống nhất là \texttt{clk}.
        \item Tín hiệu khởi động reset hệ thống tích cực thấp dị bộ là \texttt{rst\_n}.
        \item Các thanh ghi nội bộ (Internal Registers) sử dụng tiền tố \texttt{r\_} để phân biệt rõ với net (\texttt{r\_st}, \texttt{r\_cont}, \texttt{r\_pre\_start}, \texttt{r\_m\_start}).
    \end{itemize}
    \item \textbf{Parameterization (Tham số hóa hằng số)}: Chuyển đổi hằng số cứng \texttt{16} (giới hạn đếm chia tần số) thành một \texttt{parameter CLK\_DIV = 16}, giúp cấu hình lại dễ dàng tùy theo môi trường tần số hoạt động của chip mà không cần sửa đổi logic cốt lõi.
    \item \textbf{FSM State Definition}: Sử dụng \texttt{localparam} thay thế các số nguyên thô (\texttt{0, 1, 2, 3}) bằng các trạng thái có nghĩa thực tế (\texttt{ST\_IDLE}, \texttt{ST\_SETUP}, \texttt{ST\_EN\_HIGH}, \texttt{ST\_EN\_LOW}).
    \item \textbf{Latching Prevention}: Bổ sung nhánh \texttt{default} vào cuối câu lệnh \texttt{case} để đảm bảo tính an toàn hệ thống, tránh tổng hợp sinh ra chốt trạng thái (latch) ngoài ý muốn khi có nhiễu trạng thái.
    \item \textbf{Compile Bug Fixing}: Sửa lỗi cú pháp nghiêm trọng của mã nguồn gốc. Ở khối reset ban đầu, biến \texttt{prestart} (chữ \texttt{s} thường) bị gán mặc dù khai báo là \texttt{preStart} (chữ \texttt{S} hoa). Điều này khiến trình biên dịch báo lỗi biến chưa được định nghĩa. Đã chuẩn hóa lại thành \texttt{r\_pre\_start}.
    \item \textbf{Thụt lề và Bố cục chuẩn (Indentation \& Readability)}: Toàn bộ cấu trúc khối \texttt{always}, \texttt{if-else}, \texttt{case-endcase} được định dạng nhất quán bằng khoảng trắng (spaces) giúp mã nguồn đạt tính thẩm mỹ công nghiệp.
\end{enumerate}

\end{itemize}

\section{Bài 3: Layout cổng NOR 3 ngõ vào \& Diện tích (1.0 điểm)}

\subsection{a) Bản vẽ Layout cổng NOR 3 ngõ vào theo nguyên tắc Lambda}
Để thiết kế layout có tính cân bằng và hiệu năng cao, ta áp dụng công nghệ Lambda-based ($\lambda$) với các quy chuẩn kích thước tối thiểu sau:
\begin{itemize}
    \item Độ rộng đường ray nguồn $V_{DD}$ và $GND$ (Metal 1): $4\lambda$.
    \item Chiều rộng vùng khuếch tán P-diffusion ($W_p$): $6\lambda$ (để tăng kích cỡ PMOS mắc nối tiếp nhằm bù lại độ cơ động hạt dẫn $\mu_p \approx \frac{1}{2} \mu_n$).
    \item Chiều rộng vùng khuếch tán N-diffusion ($W_n$): $3\lambda$ (NMOS mắc song song có dòng tốt nên giữ kích thước tối thiểu).
    \item Độ rộng cổng Polysilicon ($L$): $2\lambda$.
    \item Khoảng cách tối thiểu Poly-to-Poly: $3\lambda$.
    \item Kích thước tiếp điểm Contact (Metal-to-Active / Metal-to-Poly): $2\lambda \times 2\lambda$, bao bọc bởi Active/Poly tối thiểu $1\lambda \rightarrow$ kích thước vùng tiếp xúc là $4\lambda \times 4\lambda$.
\end{itemize}

\subsection{b) Tính toán diện tích cổng NOR 3 ngõ vào}
Chúng ta tính toán kích thước chiều rộng ($W$) và chiều cao ($H$) tối thiểu của cell dựa trên luật thiết kế khoảng cách:

\subsubsection{1. Tính chiều rộng của cell ($W$):}
\begin{itemize}
    \item \textbf{Cổng Poly}: $3 \times 2\lambda = 6\lambda$.
    \item \textbf{Khoảng cách giữa các cổng (Poly-to-Poly)}: $2 \times 3\lambda = 6\lambda$ (đủ diện tích đặt Contact và đảm bảo cách ly).
    \item \textbf{Overlap từ Poly ngoài cùng đến mép Diffusion}: $2 \times 2\lambda = 4\lambda$.
    \item \textbf{Khoảng đệm an toàn đến đường biên cell}: $2 \times 2\lambda = 4\lambda$.
    \item $\Rightarrow$ \textbf{Tổng chiều rộng $W$} = $6\lambda + 6\lambda + 4\lambda + 4\lambda = 20\lambda$.
\end{itemize}

\subsubsection{2. Tính chiều cao của cell ($H$):}
\begin{itemize}
    \item \textbf{Đường ray nguồn VDD (Metal 1)}: $4\lambda$.
    \item \textbf{Độ cách ly VDD đến P-Active}: $3\lambda$.
    \item \textbf{Độ rộng vùng P-Active ($W_p$)}: $6\lambda$.
    \item \textbf{Độ cách ly P-Active to N-Active}: $6\lambda$ (khoảng cách tối thiểu giữa giếng N-well và Substrate để chống hiện tượng Latch-up).
    \item \textbf{Độ rộng vùng N-Active ($W_n$)}: $3\lambda$.
    \item \textbf{Độ cách ly N-Active đến GND}: $3\lambda$.
    \item \textbf{Đường ray đất GND (Metal 1)}: $4\lambda$.
    \item $\Rightarrow$ \textbf{Tổng chiều cao $H$} = $4\lambda + 3\lambda + 6\lambda + 6\lambda + 3\lambda + 3\lambda + 4\lambda = 29\lambda \approx 30\lambda$ (Chuẩn hóa cell thường lấy số chẵn là $30\lambda$).
\end{itemize}

$$\text{Diện tích cell tối thiểu } S = W \times H = 20\lambda \times 30\lambda = 600\lambda^2$$

\section{Bài 5: Script cho Synopsys Design Compiler (1.5 điểm)}

\subsection{a) Viết script đặt ràng buộc ``my\_constraints.tcl''}
Với tần số hoạt động yêu cầu $f = 150\text{ MHz}$, chu kỳ xung nhịp hệ thống sẽ là:
$$T = \frac{1}{150 \times 10^6} = 6.67\text{ ns}$$

Mã kịch bản TCL cấu hình ràng buộc thời gian (Timing Constraints) cho Synopsys DC như sau:

\begin{lstlisting}[language=tcl, caption={my\_constraints.tcl}]
# =====================================================================
# SYNOPYS DESIGN COMPILER CONSTRAINT SCRIPT: my_constraints.tcl
# =====================================================================

# 1. Define Clock Period (150 MHz corresponds to 6.67ns)
create_clock -name "sys_clk" -period 6.67 [get_ports CLK]

# 2. Clock Latency
set_clock_latency 1.0 [get_clocks sys_clk]

# 3. Input Delays for control signals (CLK_EN, Reset)
set_input_delay -clock sys_clk 1.0 [get_ports CLK_EN]
set_input_delay -clock sys_clk 1.0 [get_ports Reset]

# 4. Input Delay for general data port (Data_in)
set_input_delay -clock sys_clk 5.0 [get_ports Data_in]

# 5. Output Delay for output port (Data_out)
set_output_delay -clock sys_clk 5.0 [get_ports Data_out]

# 6. Fanout Constraints (Max fanout of 5 for all outputs)
set_max_fanout 5 [get_ports Data_out]

# 7. Output Load Constraint (Capacitive Load of 0.1 pF)
set_load 0.1 [get_ports Data_out]

# 8. Maximum Transition Limit for high performance
set_max_transition 1.0 [current_design]

# =====================================================================
# END OF SCRIPT
# =====================================================================
\end{lstlisting}

\subsection{b) Script biên dịch thiết kế theo Top-Down Strategy}
Chiến lược tổng hợp Top-Down cho phép tối ưu hóa toàn bộ hệ thống bằng cách phân bổ lại tài nguyên thời gian giữa các khối con. Kịch bản tổng hợp hoàn chỉnh dưới đây đáp ứng đúng yêu cầu giải phóng các phân cấp (ungroup) và biên dịch chất lượng cao (high-effort):

\begin{lstlisting}[language=tcl, caption={top\_down\_compile.tcl}]
# =====================================================================
# TOP-DOWN COMPILATION STRATEGY SCRIPT
# =====================================================================

# 1. Read Design Files (Top-level and sub-modules)
analyze -format verilog {Top_system.v FFT.v Filter_bank1.v Filter_bank2.v Alpha.v Beta.v Rate.v}
elaborate Top_system
current_design Top_system

# 2. Source Environmental and Timing Constraints
source my_constraints.tcl

# 3. Apply Ungrouping to Filter_bank1 and Filter_bank2
# This flattens their boundaries to allow cross-boundary optimization
set_ungroup [get_cells -hierarchical *Filter_bank1*] true
set_ungroup [get_cells -hierarchical *Filter_bank2*] true

# 4. Verification before compilation
link
check_design

# 5. Compile with High Effort Strategy
# -map_effort high optimizes timing intensely
# -area_effort high aggressively minimizes silicon area
compile -map_effort high -area_effort high

# 6. Report generation
report_timing > timing_report.rpt
report_area > area_report.rpt
report_constraint -all_violators > constraint_violators.rpt

# 7. Save Optimized Netlist
write -format ddc -hierarchy -output Top_system_optimized.ddc
write -format verilog -hierarchy -output Top_system_netlist.v
\end{lstlisting}

\section{Bài 7: Binary Decision Diagram (BDD) (1.0 điểm)}

Cho hàm logic:
$$f = a'bcd' + abc'd'$$

\subsection{a) Rút gọn biểu thức}
Ta thực hiện rút gọn đại số Bool trước khi vẽ BDD:
$$f = b \cdot d' \cdot (a' \cdot c + a \cdot c')$$

Nhận xét thấy $(a' \cdot c + a \cdot c')$ chính là phép toán XOR giữa $a$ và $c$ ($a \oplus c$). Do đó:
$$f = b \cdot d' \cdot (a \oplus c)$$

Để tối ưu kích thước của Binary Decision Diagram và biến đổi nó thành \textbf{ROBDD} (Reduced Ordered BDD), ta phân tích theo hai thứ tự biến quyết định:

\subsection{b) Bản vẽ ROBDD tối ưu theo thứ tự biến ($b \rightarrow d \rightarrow a \rightarrow c$)}
Với thứ tự này, ta có thể nhanh chóng cắt tỉa (pruning) các nhánh có $b=0$ hoặc $d=1$ để đưa về nút lá $0$ mà không cần kiểm tra các biến khác, giúp tối ưu diện tích lưu trữ và tốc độ xử lý của thuật toán tổng hợp logic.

Quy ước vẽ:
\begin{itemize}
    \item \textbf{Đường nét đứt (- - -)}: Nhánh quyết định nhận giá trị $0$.
    \item \textbf{Đường nét liền (---)}: Nhánh quyết định nhận giá trị $1$.
\end{itemize}

\section{Bài 8: Tối ưu hóa thiết kế phần cứng Datapath (1.0 điểm)}

\subsection{a) Tối ưu hóa sơ đồ tính toán số học Datapath}

\subsubsection{1. Common Subexpression Elimination (CSE - Loại bỏ biểu thức chung):}
*   \textbf{Ban đầu}: Ta có 2 phương trình logic song song:
    $$F1 = (X0 \times X1) + (X2 \times X3)$$
    $$F2 = (X2 \times X3) - (X4 \times X5)$$
    Thiết kế ban đầu cần \textbf{3 bộ nhân (Mul)}, \textbf{1 bộ cộng (Add)} và \textbf{1 bộ trừ (Sub)}.
*   \textbf{Tối ưu hóa}: 
    Ta nhận diện biểu thức chung $T = X2 \times X3$. Chúng ta thực hiện tính toán giá trị trung gian $T$ trước bằng một bộ nhân duy nhất, sau đó định tuyến kết quả của bộ nhân này đến cả bộ cộng và bộ trừ:
    $$F1 = (X0 \times X1) + T$$
    $$F2 = T - (X4 \times X5)$$
    $\rightarrow$ Thiết kế lúc này chỉ cần \textbf{2 bộ nhân (Mul)}, tiết kiệm được nguyên 1 bộ nhân lớn (giảm tới 33.3% tài nguyên nhân).

\subsubsection{2. Resource Sharing (Chia sẻ tài nguyên phần cứng):}
Nếu hệ thống hoạt động đa chu kỳ (multi-cycle scheduling), ta có thể tối ưu hơn nữa bằng cách chia sẻ bộ nhân và bộ ALU thông qua các bộ chọn kênh Multiplexer (MUX):

\subsection{b) Tối ưu hóa sơ đồ cổng logic tổ hợp (Combinational Logic Optimization)}
*   \textbf{Ban đầu}: Sơ đồ logic nguyên bản có cấu trúc:
    $$F1 = \overline{A \cdot B} + \overline{C + D}$$
    $$F2 = \overline{A + B} + \overline{C \cdot D}$$
    Thiết kế nguyên bản sử dụng: 2 cổng NAND2, 2 cổng NOR2, 2 cổng OR2.
    Tính toán số lượng transistor ở cấp độ vật lý:
    \begin{itemize}
        \item 2 cổng NAND2: $2 \times 4 = 8$ transistors.
        \item 2 cổng NOR2: $2 \times 4 = 8$ transistors.
        \item 2 cổng OR2 (gồm NOR2 + INVERTER): $2 \times (4 + 2) = 12$ transistors.
        \item $\Rightarrow$ \textbf{Tổng cộng} = $8 + 8 + 12 = 28$ transistors.
    \end{itemize}
*   \textbf{Tối ưu hóa logic sâu (Deep Logic Optimization)}:
    Áp dụng định lý De Morgan:
    $$F1 = \overline{A \cdot B} + \overline{C + D} = \overline{ (A \cdot B) \cdot (C + D) }$$
    $$F2 = \overline{A + B} + \overline{C \cdot D} = \overline{ (A + B) \cdot (C \cdot D) }$$
    
    Thay vì sử dụng các cổng logic riêng lẻ rời rạc như thiết kế cũ, ta sử dụng các \textbf{cổng logic phức tạp (Complex Gates / Standard Cells)} tích hợp sẵn của thư viện ASIC:
    \begin{itemize}
        \item $F1$ tương đương hoàn toàn với 1 cổng logic phức tạp \textbf{AOI22} (AND-OR-INVERT). Mạng NMOS (PDN) gồm (A nối tiếp B) song song với (C nối tiếp D) $\rightarrow$ tốn 8 transistors.
        \item $F2$ tương đương hoàn toàn với 1 cổng logic phức tạp \textbf{OAI22} (OR-AND-INVERT). Mạng PMOS và NMOS đấu đối ngẫu tương đương $\rightarrow$ tốn 8 transistors.
    \end{itemize}
    
    $$\text{Tổng số transistor của thiết kế tối ưu } = 8 \text{ (F1)} + 8 \text{ (F2)} = 16 \text{ transistors}$$
    
    \textbf{Đánh giá kết quả tối ưu}:
    \begin{enumerate}
        \item \textbf{Diện tích Silic}: Tiết kiệm tới $\frac{28 - 16}{28} \times 100\% = \mathbf{42.8\%}$ diện tích cell.
        \item \textbf{Hiệu năng (Delay)}: Giảm độ trễ đường truyền từ 2 tầng cổng logic thô xuống chỉ còn 1 tầng cổng logic phức tạp duy nhất, giảm điện dung ký sinh tại các nút trung gian, nâng cao đáng kể tần số hoạt động cực đại của ASIC.
    \end{enumerate}
